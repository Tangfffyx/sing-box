# 阶段 B · 用户管理、节点授权与流量验收

在阶段 A 的 7.0.0 施工目录继续。改动随 `build.sh` 重新生成单文件 `sb.sh`。

## 实现

- 用户管理首页直接按序号打开用户详情。管理员是否允许接入单独保存，实际可用还要检查到期日及额度。菜单、后台同步与 Telegram Bot 共用判断。老数据里无法识别的停用原因显示「停用待核对」。
- 管理资料保留节点和原始认证身份。运行配置只下发当前获准的身份。某个受管入站没有获准身份时暂停监听。SOCKS5 没有匿名回退，静态 SS2022 没有单用户回退。明确删除节点才清理相应授权。协议、中转和 WARP 写入使用同样的授权投影。
- 流量按入站认证名记录计数器，再汇总到业务用户。缺少某一方向的读数时保留该方向基线。新内核进程从新一代计数开始，重复采样只记增量。额度用 GiB 显示。详情显示最后成功采样和上次可能缺计的时间。仅改账务且运行配置一致时保留进程。
- 账号状态和流量更新使用同一管理锁。同字段并发修改提示冲突。Telegram 回执的领取和写回也使用锁，重复投递的任务只执行一次。

## 实测

| 检查 | 结果 |
|---|---|
| 手动停用 | 真实旧长连接在应用权限时中断。新请求被拒。Bob 在服务启动后用旧链接重新连接。 |
| 到期及超额 | 到期当天和用量达到 1 GiB 时均拒绝接入。续期、清零、提高额度之后，用原链接成功。 |
| 暂停最后一个身份 | SOCKS5 和 SS2022 停止监听。后台同步后恢复原授权，原 SOCKS5 和 SS2022 凭据可继续使用。 |
| 重启和重复采样 | 从两个真实内核进程读取 gRPC 统计，逐项核对上行和下行累计。每份相同样本重放时账本一致。另测方向读数暂缺、节点删除、账期重置和采样失败。 |
| 并发和回执 | 编辑时新增的账本流量保留，同字段冲突被拒。重复投递一次补正任务，账本只增加一次。仅修改未触发停用的额度时不调用重启。 |
| 九协议回环回归 | 使用实际 1.14.2 内核，九种协议均通过授权状态的 TCP 和 UDP 测试，停用或未分配的身份均被拒。macOS 上用临时本地 TLS 1.3 服务替代原测试的握手目标。 |
| 全套脚本回归 | macOS 上使用 Bash 5.2 和 flock 通过 `bash tests/check.sh`。Linux 专用的 `/proc` 检查跳过，阶段 B 未在 Linux 服务环境重跑。 |

若内核退出前仍有未取得的统计，脚本无法补算这一段。计划更新权限时，最后一次采样失败会记录缺口并继续办理停用或到期。

## 重跑

使用 Bash 4 以上及 flock。真实内核测试需要支持 V2Ray gRPC 统计的 sing-box 1.14.2、grpcurl 和可用的本机回环端口。

```bash
case_dir="$(mktemp -d)"
bash tests/stage-b.sh "$case_dir"
python3 tests/stage-b-core.py /path/to/sing-box "$case_dir" /path/to/grpcurl
```
