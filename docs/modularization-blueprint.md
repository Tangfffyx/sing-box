# sb.sh 模块化拆分蓝图（不改功能语义）

## 目标
- 将单文件脚本逐步拆分为低耦合模块。
- 每一阶段都保持行为一致，可回滚。
- 每次只拆一个领域，降低回归风险。

## 当前建议目录
- `sb.sh`：入口与启动分发（仅保留主流程和 source）。
- `lib/core.sh`：通用工具（日志、校验、JSON IO、基础助手）。
- `lib/config.sh`：配置加载/校验/应用/回滚。
- `lib/protocol.sh`：协议安装/卸载/冲突检测/构建。
- `lib/export.sh`：导出链接与编码构建。
- `lib/cron.sh`：cron 管理（安装/移除/状态/UI 子菜单）。
- `lib/user.sh`：用户管理与流量统计。
- `lib/menu.sh`：主菜单和子菜单分发。

## 分阶段计划
### 阶段 1（低风险）
1. 提取 `lib/export.sh`：迁移 600 Export 区域函数。
2. 提取 `lib/cron.sh`：迁移 cron 相关函数与菜单。
3. `sb.sh` 中 source 以上模块并保持函数名不变。

### 阶段 2（中风险）
1. 提取 `lib/config.sh`：配置/服务启停/回滚事务。
2. 提取 `lib/protocol.sh`：协议安装与冲突检测。
3. 保持旧函数签名，避免上层菜单改动。

### 阶段 3（中高风险）
1. 提取 `lib/user.sh`：用户数据、授权、统计同步。
2. 提取 `lib/menu.sh`：只保留 UI 与路由。
3. `sb.sh` 变成薄入口：环境检查 + source + main。

## 验收规则（每阶段）
1. 语法：`bash -n sb.sh`
2. 协议安装：Reality/AnyTLS/TUIC 至少各走一次。
3. 端口冲突：同协议同端口必须提示冲突并重填。
4. 导出：各协议导出链接非空且可复制。
5. 定时任务：安装/移除后状态显示一致。
6. 用户管理：新增用户、授权节点、查看状态正常。

## 回滚策略
- 每个阶段独立提交，若出现回归可单独 revert。
- 不在同一提交里混入功能新增。
- 提交信息遵循：`refactor(scope): ...`。
