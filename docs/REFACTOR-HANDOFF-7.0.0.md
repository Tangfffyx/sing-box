## 重构原则与模块边界

**采用渐进式重构。** 保留模块化 Bash、独立的 Telegram Python 源码、单文件分发、管理锁和现有回归测试。集中理顺节点与用户资料的归属、配置变更的提交与恢复，以及按用户和公网入口生成导出的逻辑。

1. **保住老用户的身份和账。** 创建与编辑分开。普通编辑复用凭据、证书和统计键。用升级前的链接重连、用旧账本对账。
2. **同一条业务规则只维护一处。** 菜单、定时任务和 Bot 调用同一套授权与计量逻辑。安装页、用户详情和二维码使用同一套导出数据。
3. **一笔变更可以重试和恢复。** 在锁内提交到最新状态。配置、用户库、管理资料和受影响的本机资源能一起恢复。内容相同的重复操作应保持相同结果。
4. **优先复用可用组件。** 已有时间服务、WireProxy、证书和反代经过核验就复用。默认参数采用已证实通用的设置，有条件的优化只在已定场景开放。
5. **常用操作尽量少填。** 自动生成可生成的值。需要选择时说清实际影响，耗时步骤显示在做什么、等了多久，失败时给出可执行的下一步。
6. **分阶段用真实行为验收。** 先验证数据迁移，再验证运行配置和服务，最后从客户端验证连接、权限、路由或扫码。记录尚缺的外部实测证据。

| 职责 | 从现有代码落手 | 各入口如何共用 |
|---|---|---|
| 菜单与输入 | `00_base`、`01_utils`、`99_main`、`90_protocol_menu`、`62_user_menu` | 复用 `00_base` 的协议注册表。菜单收集本次意图，显示实际端口、异常和结果。列表、导出和 jq 的协议排序共用注册表，补测直接读取静态 jq 的调用者。耗时操作显示阶段、已用秒数和超时原因。 |
| 节点、账户与落地资料 | `20_protocol`、`60_user_db`、`61_user_manager`、`40_relay` | 区分节点身份、业务用户、用户在节点上的凭据、对外地址、落地标识。CDN 入口和中转出口可独立更新。已有 tag、用户名和流量统计键继续可识别。 |
| 配置、路由与生效 | `10_config`、`30_route`、`35_split_rule_conflict`、`61_user_manager` | 复用管理锁、配置检查、服务就绪检查和回滚。菜单、cron 和 Bot 的同类变更走同一个提交入口。已有自定义配置与脚本管理的规则分别识别。 |
| 系统与外部服务 | `80_installer`、`50_v2ray_api`、`63_telegram_bot`、`py/tg_center_bot.py`、`64_warp` | systemd/OpenRC、时钟、规则下载、WARP 探测分别返回实际结果。远端失败可以单独重试。 |
| 导出与呈现 | `70_export` 及安装完成页 | 先按授权范围得到已生效的“用户＋节点＋公网入口”，再生成 URI、YAML 或 QX。二维码直接编码 URI。列表、安装页、详情页复用这一过程。 |

表中的模块简称对应 `lib/` 下同名的 `.sh` 文件。文件拆分可以随施工调整，先沿用已经有调用者和测试的接口。

**资料归属。** 保留现有 `config.json`、`user-manager.json`、`meta.json`、Telegram 配置和任务回执。运行配置记录实际入站与生效规则。用户库记录授权、套餐、用量和计数器基线。管理资料保存运行配置无法完整还原的内容，例如暂停节点的资料、用户原凭据、WS 公网入口和落地引用。停用最后一个用户后，管理记录中仍能找到节点及原授权。私钥、注册资料及凭据只允许必要的本机进程读取，避免出现在普通列表、日志和验收附件。

**一次变更怎样提交。** 用户输入和远端探测放在锁外。准备提交时持现有管理锁，重读最新数据、合并本次改动、检查冲突，生成候选配置并运行 `sing-box check`。涉及运行配置才应用并验证服务，再核对用户库、管理资料和运行状态一致。跨文件更新留下可恢复的上一个版本或事务记录。中断后能完成或恢复整笔变更。引入证书、反代、防火墙或外部服务时，记录哪些资源由本次创建，以及失败时各自如何恢复。修改额度等未改变运行配置的操作应保留服务 PID。

### 交互体验怎样验收

以下规则随各阶段的菜单一起实现，阶段 I 用发布包走一遍。

| 用户在做什么 | 界面应当怎样表现 | 怎样验收 |
|---|---|---|
| 第一次装节点，或再次使用已有配置 | 推荐值放在回车选项，特殊需求进「自定义」。装好一个节点直接显示该节点的链接或二维码。输入有误就停在出错处，保留本次已经填对的内容。 | 用空闲端口按默认方案装 HY2，从推荐页回车直到出现导出结果，途中无需再填端口、密码或跳跃范围。再导出已有 WS 节点，已保存的 CDN 域名无需重填。 |
| 等待下载、校时或网络验证 | 开始时先显示正在做什么。下载能取得总量时显示真实进度。握手、等待服务等时长未知的步骤持续更新已用时间，例如「正在验证 WARP 出口，已等待 8 秒」。超时后说清卡在哪一步，给出可行的重试或返回入口。 | 分别模拟慢下载、远端无响应和快速成功。慢操作期间能看见状态更新，超时后能继续操作，快操作无需等动画播完。定时任务和重定向输出保持逐行可读，复制出的链接不混入进度文字。 |
| 在手机 SSH 里看菜单和处理错误 | 标题、状态、可选操作的顺序一致。提示用一句话讲清当前情况及下一步。窄屏改用单列，颜色只作辅助。打开首页和返回上级直接读本机资料，远端连通性在相应操作里检查。 | 在窄屏和关闭颜色的终端中走完添加节点、扫码或复制、返回三步。临时断开外网后仍能打开首页和返回。落地认证失败时，用户能看懂该检查哪份凭据，并在当前步骤重新粘贴。 |

## 施工阶段与验收

先用 A、B 固定旧数据和权限行为。C 定下新建、编辑和导出的共用规则，D、E 在这个基础上接入 CDN 和落地机。F 接通各导出入口，G 接入 WARP，H 完成菜单引导，I 用实际发布包验收和定稿 README。

### A · 固定基线，先保护存量数据

**施工。** 先在 7.0.0 上运行现有回归并保存结果。用虚构数据制作升级样本，包含管理员、两名普通用户、直连与中转、多协议、已停用账号、既有证书、历史流量、手工路由和缺少 CDN 域名的 WS。保存可工作的老客户端配置作后续对照。读取用户库时，只有确认首次使用且文件不存在才初始化。已有空文件、无效 JSON、缺少 admin，或老安装中文件意外缺失，都应保护原件并提示恢复。

迁移先从现存入站、用户库和管理资料提取已有值，保留仍有效的凭据、证书、端口、账期、计数器和 TG 绑定。无法恢复的旧秘密标记“需补录”，由管理员选择导入或显式轮换。备份覆盖脚本、运行配置、管理资料、证书及受影响的服务配置，同一次回退恢复相互匹配的文件。

**验收。** 迁移样本运行两次，第二次凭据、账期、计数和规则不变。进入损坏用户库的菜单、运行 cron、执行 Bot 用户操作，都不能覆盖旧库。模拟写入失败和提交中断，恢复后两名用户的原链接可用，用户权限、数据和运行配置一致。迁移本身不应给任何用户扩大权限。

### B · 用户管理、授权与记账（第 9 项）

**施工。** 先保存“管理员是否允许使用”和各节点原始凭据，再计算实际状态。实际可用须同时满足管理员允许、未到期、额度尚有余额或不限额。识别旧的 `quota` / `quota_exceeded`、`expired`、`manual` 等原因。老数据原因不明的停用账号维持停用并提示核对。菜单、定时任务和 Bot 都调用同一判断。到期日沿用现有“当天停用”语义。

生成运行配置时，只允许已授权且当前可用的身份接入。直连、中转、自定义规则都受这个条件约束。特别检查 `user_db_cleanup_missing_nodes`，它目前从运行配置枚举节点。暂停最后一个 SOCKS5 监听后，权限清理应以管理资料中的节点为准，只有明确删除节点才撤掉分配。否则恢复账户时，即使找回了密码，用户也可能已经失去节点授权。

进入「用户管理」即显示列表，选用户即进详情，提供启停、续期、限额、节点权限和导出。计费量显示上传＋下载＋手动补正，额度单位明确为 GiB。保留按节点认证身份采样、汇总到业务用户的增量记账。流量最后成功采样时间单独更新。每 3 分钟周期检查一次。采样失败保留已知值，依然执行已有依据的手动停用和到期处理。若权限变更需要重启且最后一段流量未采到，记录这个缺口。

**验收。**

| 操作 | 可观察结果 |
|---|---|
| 1 GiB 账号用完后清零，或把额度提高到已用量以上 | 保存后即可用原链接连接。同时到期者仍显示已到期。手动停用者跨重置日仍停用。 |
| 有自定义放行规则时停用用户，再恢复 | 旧长连接实际中断，新连接被拒。恢复后原链接通。记录其他在线用户是否短暂断线及恢复情况。 |
| 停用最后一个 SOCKS5 用户，在暂停期间运行后台同步并重启，再启用 | 监听暂停，无免认证入口。节点资料、授权和凭据仍在，恢复后原落地链接可用。 |
| 静态多用户 SS2022 节点的最后一个授权身份被停用，再恢复 | 在无人获准时暂停该受管入站，验证原链接和单用节点密钥均无法接入。恢复用户后用原链接连通。sing-box 1.14.2 会将无静态用户、无中继目标的普通入站解释成单用户模式，不能用空列表表达“所有人都停用”。[入站选择逻辑](https://github.com/SagerNet/sing-box/blob/v1.14.2/protocol/shadowsocks/inbound.go#L32-L45) |
| 连续采相同读数、重启内核、删除其中一个节点、跨月或闰年月末重置 | 相同增量只记一次。保留历史总量。实际重置每账期一次。采样故障时最后成功时间不前移。 |
| 菜单停在编辑时 cron 入账，或 Bot 同时改同一用户 | 额度变更保留新增流量，同字段冲突可见。同一 Bot 任务重发只生效一次。仅改账务且认证未变时 PID 不变。 |

### C · 协议默认值、导出字段与校时（第 3、5、6 项）

**施工。** 先补各协议“导出→解析→还原原值”的样本，再接推荐安装。推荐页展示实际选择，回车安装，`c` 进入自定义。每种协议共用新建、分配用户和导出的凭据规则。普通编辑读取原值。端口按 TCP/UDP 分开检查，UDP 还检查 HY2 跳跃段。公网 IPv4、IPv6、域名及 NAT 映射与本机监听分开保存。自签证书复用有效材料，受信任证书正常验证。去掉外站 SNI 测速，Reality 单独检查真实握手目标。

区分“该端口正被另一个服务占用”和“这是已有的同协议受管节点”。前者推荐其他空闲端口，后者进入编辑并展示会改动的字段。公共模板沿用内核的 QUIC 窗口、MTU 探测及 TCP/TLS 默认值。已有节点明确配置的兼容参数由普通编辑保留。

| 协议（即显示顺序） | 推荐入站与自动配置 | 导出与专门验收 |
|---|---|---|

### D · 两种 WS 接入已有 CDN（第 4 项）

**施工。** 本期对接用户已有、允许该用途的 CDN。公网域名已绑定、CDN 支持 WebSocket、回源配置可用时，只问一次公网入口域名并保存。同一域名可按路径连接两种协议，各自保有 UUID 和用户记录。由同机反代接收 CDN 的 HTTPS 回源请求。反代后面的 sing-box WS 入站默认只监听回环地址，VMess 优先 8001、VLESS 优先 8002，冲突选空闲端口。优先复用已有反代，修改前检查配置，失败恢复该站点。验证 CDN 到源站的 HTTPS 及源站证书，同机反代到 sing-box 的一段可用普通 WS。若 443 已被独占，根据提供商支持使用独立 HTTPS 回源端口。旧节点缺域名只补录一次，保留 UUID、路径、监听地址及用户。

普通 CDN 导出的连接地址、SNI 和 WS Host 使用公网入口域名，对外默认 443。服务端保留 `max_early_data: 2048` 和 `early_data_header_name: "Sec-WebSocket-Protocol"`，存储纯路径。通用链接、QX 默认纯路径，QX 验证公网证书。Mihomo 在实际链路可透传时才输出 Early Data 选项。默认线路名「VLESS-WS · CDN 自动」或相应 VMess 名称。提供商确有独立入口才标「电信入口」等，导出中使用该入口的实际连接参数。称“优选”需有对应运营商、地区、日期及多次端到端对照。多个真实入口共用一个用户配额。

**验收。** 用已配置的 CDN 从公网分别经 VMess-WS 和 VLESS-WS 完成真实代理请求，同域两个路径各连对节点。核对通用链接、Mihomo、QX 的实际拨号地址均为公网入口。源站 IP 和本地监听端口不会出现在普通 CDN 配置的拨号地址中。普通 WS 与支持的 Early Data 均测。域名、证书、回源端口、路径或认证有误时指出已查明的失败环节。缺少合格入口资料时提示补录。已有 CDN 成功接入后，再次导出可直接读取已存域名。只有一个入口时只导出一条默认线路。模拟给同一站点加第二条路径失败，第一条已有客户端链接仍可用。

**后续范围。** 从零开通 CDN 另立项目，有实际需求时优先评估 CloudFront。本期 WS 安装、重试和卸载只修改脚本管理的本机节点及反代配置，沿用用户现有的云端授权和计费设置。

### E · SOCKS5 落地与中转（第 7、8 项）

**施工。** 安装处提示「推荐在落地机安装。装好后复制落地链接，到中转机粘贴。」中转菜单提示「客户端连接本机，流量从落地机出去。请先在落地机用本脚本安装 SOCKS5，再复制落地链接。」

落地机生成 `socks5://用户名:密码@地址:端口`，用户名和密码分别编码，IPv6 加方括号。允许自定义两机可达的地址及映射端口。中转机首次只问链接和落地标识，实际连通且通过 SOCKS5 认证后保存。已有落地直接选标识。全量中转和按网站中转共用导入，保留第三方手动填写入口。全量中转只有一个本机入口时自动选中。多入口或选网站时只询问尚未确定的选择。改同一标识时显示受影响线路，更新被引用的出口资料，复用每个入口用户的原凭据。

中转默认使用原生 UDP。「中转诊断」先验证认证后的 TCP 转发，再通过 SOCKS5 协商得到的 UDP 地址和端口验证真实回包。原生 UDP 多次失败时，用临时配置经 `udp_over_tcp` 重测同一目标。测通后列出受影响线路，由用户决定是否为本机上的该落地标识启用，并提供「恢复原生 UDP」。两种方式都失败或用户取消时，保留原设置。验收覆盖原生 UDP 成功、仅 `udp_over_tcp` 成功、两者均失败三种情况，并检查其他落地及原有 TCP 中转。

**验收。** 两台测试机分别验证全量与按网站两种转发，核对真实出口。重复粘贴相同资料不新增记录。替换成功后旧客户端链接从新出口访问。粘贴错误密码或用户取消时，旧线路仍可用。普通列表及日志不回显密码。验证 IPv6、域名、NAT 和含 `@:/%` 的原凭据。

### F · 导出与本地二维码（第 10 项）

**施工。** 将导出范围和业务用户名分开传递，统一首页、用户详情及安装完成页。首页默认管理员。用户详情只显示该用户可用节点。装一个直接展开，装多个只列本批。无效输入停在原菜单，只有明选“导出全部”才扩大范围。

一次只展开一个节点。宽屏左侧节点名＋二维码、右侧格式选择。窄屏上下排列，二维码放不下时优先完整链接。右侧顺序为通用链接、Clash/Mihomo、Quantumult X。SOCKS5 第一项叫“落地链接”。选择格式后单独输出未着色、未人为换行的原文。批量一次导出一种格式。按需复用或安装本地 `qrencode`，失败仍能复制文本。删除 Surge 的菜单、生成路径和文档示例。缺少必要资料或格式无法表达节点时显示具体原因。

**验收。** 三个入口分别测试管理员、普通用户、单节点、本批多节点和无效输入，检查无越权导出。`admin` 详情能看到管理员节点。解码二维码与完整 URI 逐字节相同，再在目标客户端实际扫描导入。覆盖宽／窄终端、中文、IPv6、旧密码中引号或特殊字符、二维码工具安装失败。TUIC 本期提供通用链接和 Mihomo。HY2 Gecko＋跳跃在 QX 真机通过后才标支持。Reality 缺公钥先尝试从实际私钥恢复。无法恢复的公钥、没有补录的 WS 域名，均只提示待修节点，其他有效节点照常导出。

### G · WARP 自动分流（第 11、12 项）

**施工。** 菜单显示「让选中的网站走 WARP。首次使用会自动配置。」预设和自定义都先选网站，再检测。已分配给中转的同一规则，显示影响并请用户决定是否改走 WARP。后台依次完成以下操作。

1. 有 WireProxy 时，识别实际 SOCKS5 监听地址、端口及必要认证，经该代理访问 Cloudflare trace。读到 `warp=on` 或 `warp=plus` 后，将测通的地址、端口和认证用于分流。支持自定义端口和 IPv6 回环。避免把首个监听端口或管理端口误当 SOCKS5。已停止的外部服务询问是否启动，现有服务连接失败时显示原因并可重试。
2. 全新机器先检查实际内核具备用户态 WireGuard 能力。首次经用户同意条款，用固定版本、校验下载的第三方 `wgcf` 注册并保存本机资料，再由 sing-box 用户态 WireGuard 端点建立出口。注册已经成功而握手超时，重试复用原资料。下载、连接和应用时显示已等待秒数。[sing-box WireGuard 端点](https://sing-box.sagernet.org/configuration/endpoint/wireguard/) · [wgcf](https://github.com/ViRb3/wgcf)
3. 先用隔离的候选路径强制经目标出口探测，再提交网站分流。7.0.0 的路由重建只查 `outbounds` 里的 `warp`，要能同时识别 `endpoints`。规则按已有用户／入口范围应用。规则下载、出口验证和配置应用的失败均须可辨认。删除最后一个网站后撤销分流，外部 WireProxy 的所有权仍归原安装工具。

**验收。** Ubuntu、Debian、Alpine 分别覆盖新装、复用和重启恢复。通过真实节点各访问一个命中和一个未命中的目标，核对对应出口、其他中转规则、宿主机默认路由及 SSH 连通性。覆盖普通 SOCKS 但非 WARP、端口已开但隧道坏、注册不可达、已有 IPv6 监听、重复启用、清空规则、应用失败回退。仅支持 TCP CONNECT 的旧 WireProxy 另测浏览器 HTTP/3 回退，不能让选中网站悄悄改用直连。
