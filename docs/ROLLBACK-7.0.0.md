# 退回升级前的 7.0.0

基线与本次施工版都显示 7.0.0。用升级前保存的脚本哈希、Git 提交和内核版本识别快照。

1. **升级前留存。** 安排维护窗口。先通过当前脚本的周期同步采样，再暂停该脚本的同步、维护和 Telegram 上报任务。停止 Telegram 与 sing-box 后，将脚本、快捷命令、当前内核、统计组件、`/etc/sing-box` 和整个 `/etc/sing-box-manager` 放进同一份带时间戳的备份。包括证书、元数据、用户库、采样基线、Bot 绑定和 WARP 资料。备份仅限管理员读取。
2. **记录系统配置。** 另外保存 sing-box、Bot、HY2 恢复相关的 systemd/OpenRC 服务文件、自启和 root cron。记录由脚本管理的 HY2 防火墙规则及其范围、相关 Nginx 站点和 WS 片段，并记下原内核进程版本、已知可用的旧节点链接与用户用量。
3. **回退前留证。** 暂停任务，采集升级后的末次可用流量，停止受影响服务。把当前配置和账本另存，便于找回快照之后的变化。
4. **恢复成套快照。** 按保存的路径恢复旧脚本、快捷命令、兼容内核、配置和管理数据。对照差异恢复涉及的服务文件、Nginx 片段和 HY2 规则。对 Nginx 先做配置检查，再重载；只处理受此次升级影响的规则。不要把新旧用户库或采样状态拼成一套。
5. **确认运行。** 用恢复的二进制执行 `sing-box check -c /etc/sing-box/config.json`。恢复对应服务管理器和定时任务，核对正在运行的进程版本、统计 API 和服务稳定性。用旧链接重连，测试停用用户不能访问、已授权用户能访问、已有中转出口正常、Bot 绑定仍可查询。恢复后产生新流量并连续采样两次，检查累计正常且未重复记账。

恢复快照会把累计量还原到快照时间。保留回退前另存的账本，将快照之后能确认的差额按用户逐一核对。确需补录时，先确认运行中的计数器已建立新基线，再通过「用户管理」补正，避免把同一段流量重复计入。快照后尚未采样的尾部字节无法可靠重建。
